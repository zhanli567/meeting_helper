# ADR 0001：查询先行，禁止模型直接写数据库

## 状态

已接受。

## 背景

会议排座助手已经有完整的人工排座和保存流程。智能体能力初期风险主要来自模型误解、工具误用、结构化输出错误和权限边界不清。

用户期望的操作模式是：模型可以辅助修改前端页面草稿，页面变化后由用户人工确认并点击保存，才落到数据库。

## 决策

第一阶段只开放只读查询工具。

模型不得直接调用保存排座、发布版本、恢复版本、删除会议、删除人员等持久化动作。

后续即使开放草稿操作，也只允许修改前端草稿状态，不直接落库。

## 后果

优点：

- 降低智能体初期风险。
- 不破坏现有人工工作流。
- 易于验证工具调用、流式输出和观测链路。
- 便于在外部开发环境调试。

代价：

- 第一阶段不能完成真正自动排座保存。
- 草稿操作阶段需要设计前端命令协议。
