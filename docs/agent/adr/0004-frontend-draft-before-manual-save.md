# ADR 0004：前端草稿操作先于人工保存

## 状态

已接受。

## 背景

用户希望智能体可以像人一样操作当前排座页面，例如把人员移动到座位、批量排座、调整页面展示。但这些操作不应自动保存，用户需要确认后再点击现有保存按钮。

## 决策

后续草稿操作阶段，智能体只产生前端草稿命令或调用前端草稿工具。

前端执行命令后更新 workspace store 和页面显示，标记 dirty。数据库不变化。用户点击保存后，沿用现有保存接口和后端校验落库。

## 后果

优点：

- 符合当前人工排座流程。
- 降低误操作落库风险。
- 用户可以撤销、调整或放弃智能体结果。

代价：

- 需要设计前端命令协议。
- 需要处理前端草稿状态与智能体运行状态的一致性。
