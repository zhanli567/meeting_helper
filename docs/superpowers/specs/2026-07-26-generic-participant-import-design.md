# 通用人员导入与扩展字段设计

## 1. 目标

在不预先区分颁奖会、研讨会、培训会等会议类型的情况下，用一套人员模型和一份 Excel 模板完成参会人员导入、搜索、分组、排座、版本快照和导出。

第一版遵循最小实现原则：

- Excel 只强制要求“工号”和“姓名”两列。
- 其余非空表头全部作为当前会议的扩展字段。
- 同一会议历次导入发现的扩展字段取并集。
- 同一人员允许具有多条动态数据记录，以保留 Excel 重复人员行内各字段的对应关系。
- 所有扩展字段第一版统一按文本处理，并默认支持搜索和分组。
- 不实现扩展字段改名、类型配置、启停、权限和高级校验。

## 2. 核心概念

### 2.1 会议人员

会议人员代表“某个员工参加某场会议”，同一会议内以工号唯一。人员固定保存：

- 工号；
- 姓名；
- 出席状态；
- 审计和逻辑删除信息。

排座关系继续由排座项与场馆元素关联，不写入人员表。

### 2.2 会议扩展字段

会议扩展字段是从 Excel 非必填列中自动发现的表头。例如：

- 颁奖会：批次、奖项名称、项目名称；
- 研讨会：所属小组、发言主题；
- 培训会：课程名称、班级、是否考试。

字段定义属于会议，不属于具体人员。后续 Excel 没有某个已有字段时，不删除字段，也不删除历史值。

### 2.3 人员动态记录

一条人员动态记录对应 Excel 中去重后的一行扩展数据。一个人员可以没有动态记录，也可以有多条动态记录。

例如同一人员获得两个奖项时保存为：

```json
[
  {
    "批次": "第二批",
    "奖项名称": "优秀项目奖"
  },
  {
    "批次": "第三批",
    "奖项名称": "创新奖"
  }
]
```

记录必须整体保存，不能把每一列独立合并成数组，否则会丢失批次与奖项之间的对应关系。

## 3. 最小数据模型

### 3.1 `t_participants`

保留：

- `id`
- `meeting_id`
- `employee_no`
- `name`
- `attendance_status`
- 通用审计、逻辑删除和乐观锁字段

约束：

- `meeting_id + employee_no` 唯一；
- 工号格式为 8 位数字或 1 个小写字母加 8 位数字；
- 姓名不能为空。

职级、部门、人员类型、标签不再作为固定人员字段，统一由扩展字段承载。人员锁定状态以排座项为准，不在人员表重复保存。

### 3.2 `t_meeting_participant_fields`

第一版只保存实现功能所需字段：

- `id`
- `meeting_id`
- `field_name`
- `sort_order`
- 通用审计、逻辑删除和乐观锁字段

约束：

- `meeting_id + field_name` 唯一；
- 字段名称去除首尾空格后不能为空；
- “工号”和“姓名”为保留名称，不能注册为扩展字段。

第一版不增加字段编码、字段类型、是否搜索、是否分组等配置字段。所有扩展字段统一按字段名称寻址、按文本处理，并默认支持搜索和分组。

### 3.3 `t_participant_records`

第一版保存：

- `id`
- `participant_id`
- `record_order`
- `attributes_json`
- 通用审计、逻辑删除和乐观锁字段

`attributes_json` 保存一条 Excel 数据行中除工号、姓名之外的完整键值集合。`record_order` 按第一次成功导入该记录时的顺序递增，用于确定各字段的主值和重复值。

第一版不建立导入批次表。导入历史、整批撤销和来源文件追踪留到评审后按需要增加。

### 3.4 移除颁奖专用存储

`t_award_records` 及对应实体、仓储和专用工作区聚合由通用人员动态记录替代。系统不再为会议场景建立专用人员业务表。

## 4. 单一 Excel 模板

系统只提供一份人员导入模板，首行默认只有：

```text
工号 | 姓名
```

用户可以在“姓名”之后增加任意非空且不重复的表头。上传时：

1. 去除表头首尾空格；
2. 校验存在“工号”和“姓名”；
3. 校验表头名称不重复；
4. 将其余表头按 Excel 顺序注册或复用为会议扩展字段；
5. 空白扩展单元格不写入 `attributes_json`。

上传接口不再要求模板类型，前端也不再展示通用会议和颁奖会议模板选择。

## 5. 行解析与重复处理

### 5.1 空行

整行为空时忽略。

### 5.2 完全重复行

工号、姓名以及全部扩展字段值完全相同时自动去重，只保留首次出现的一行。

比较前对表头和值去除首尾空格；空单元格与缺失值均按空值处理。

### 5.3 同工号、同姓名、扩展字段不同

识别为同一个人员的多条动态记录，全部保留。

### 5.4 同工号、姓名不同

识别为人员身份冲突，导入预览标记错误，不允许提交，用户修改 Excel 后重新上传。

### 5.5 会议中已存在相同工号

- 姓名相同：复用已有人员。
- 姓名不同：识别为人员身份冲突。
- 与已有动态记录完全相同：跳过，不重复保存。
- 与已有动态记录不同：追加为新动态记录。

第一版采用增量追加语义，不自动覆盖或删除已有动态记录。后续如需批量修订，可增加记录编辑和删除能力。

## 6. 工作区聚合规则

工作区返回：

- 会议扩展字段列表；
- 每个人员的动态记录列表；
- 每个人员按字段聚合后的不重复值列表。

某字段的第一个非空值为主值，后续不同值为重复值。例如：

```text
批次主值：第二批
批次重复值：第三批
```

这个规则按 `record_order` 计算，不写死“批次”“奖项”等字段名称。

## 7. 前端展示

### 7.1 单人新增

单人新增弹窗包含：

- 工号；
- 姓名；
- 当前会议已经注册的全部扩展字段。

移除写死的获奖人员、嘉宾、特邀嘉宾等人员类型选项。用户填写的扩展字段形成该人员的第一条动态记录。

### 7.2 待排和全部人员列表

- 姓名和工号固定展示。
- 按会议字段顺序展示前两个有值的扩展字段主值。
- 某字段有多个值时显示主值和附加数量。
- 搜索匹配工号、姓名以及任意动态记录中的任意扩展字段值。
- 分组选项由工号、姓名和会议扩展字段动态生成。
- 按扩展字段分组时使用该字段的主值；无值人员进入“未填写”组。
- 一个人在列表中始终只出现一次，不因多条动态记录重复出现。

人员详情展示完整动态记录表格，每条记录占一行，保留字段之间的对应关系。

### 7.3 场馆座位

座位主要展示姓名。需要补充信息时，按会议字段顺序显示首个有值的扩展字段主值，不再引用人员类型、主批次或奖项专用字段。

## 8. 导入预览

预览页展示：

- 本次总行数；
- 自动忽略的完全重复行数；
- 新增人员数；
- 已有人员追加记录数；
- 新发现的扩展字段；
- 复用的已有扩展字段；
- 工号格式、姓名为空、同工号不同姓名等错误。

只有不存在阻断错误时才允许提交。完全重复行由系统自动处理，不要求用户逐条选择。

## 9. 导出与版本

### 9.1 Excel 导出

人员工作表列顺序为：

```text
工号 | 姓名 | 当前会议扩展字段……
```

一个人员有多条动态记录时导出多行，并重复输出工号和姓名，从而支持再次导入且不丢失行级关系。没有动态记录的人员至少导出一行工号和姓名。

### 9.2 版本快照

发布版本快照必须包含：

- 会议扩展字段定义；
- 人员基础信息；
- 人员动态记录；
- 排座关系和场馆布局。

已发布版本继续只读，草稿继续允许导入和编辑。

## 10. 后端改造边界

- 用单一人员工作簿解析器替换场景导入策略。
- 删除模板类型参数和颁奖专用解析分支。
- 增加会议扩展字段与人员动态记录的实体、仓储和服务。
- 调整人员创建、导入、工作区聚合、版本恢复和导出。
- 保留现有重复工号、工号格式、临时不出席、软删除和排座能力。
- Controller、Service、Repository 的 public 方法继续提供 Javadoc。

## 11. 前端改造边界

- 导入入口只保留单一模板下载和文件上传。
- 改造导入预览以展示字段发现和多记录统计。
- 单人新增表单根据当前会议扩展字段生成。
- 人员列表、搜索、分组和座位内容改用动态记录聚合结果。
- 删除人员类型、颁奖批次和奖项的写死展示。

## 12. 验证标准

- 只有工号、姓名的 Excel 可以成功导入。
- 任意新增列会自动进入当前会议扩展字段列表。
- 历次导入的不同字段取并集，旧字段和旧值不丢失。
- 完全重复行只保存一次。
- 同工号同姓名的不同数据行保存为一个人员的多条记录。
- 同工号不同姓名阻止提交。
- 待排列表能够使用所有扩展字段搜索和分组。
- 多记录人员在列表中只显示一次，详情中完整展示多条记录。
- 颁奖示例不依赖专用奖项表也能保留批次与奖项对应关系。
- 发布版本能够完整保存并恢复扩展字段和动态记录。
- 已发布版本导出的 Excel 可以再次导入并重建相同人员数据。
