# 场馆模板模块重构设计

## 1. 目标

将场馆模板从“代码预置场馆加用户自定义场馆”重构为完全由数据库维护的通用场馆模板模块，使秘书能够自行维护不同园区、地点和物理布局的会议空间，并用同一模板重复创建多个会议。

本次重构同时明确以下系统级约束：

- 场馆模板对所有用户可见，所有用户均可创建、查看、编辑和删除。
- 不再维护代码预置场馆，也不在应用启动时初始化场馆数据。
- 场馆模板不维护草稿、发布版本或历史版本。
- 已创建会议继续保存独立的场馆布局快照，模板变化不影响历史会议。
- 所有业务表取消软删除，删除操作直接物理删除数据。
- 数据库不建立外键约束，关联关系及清理顺序由后端事务维护。
- 本期不实现画布旋转和元素旋转。

## 2. 范围

### 2.1 本期包含

- 场馆模板信息的创建、查询、编辑和删除。
- 场馆模板列表的搜索、分页和园区分组。
- 场馆信息详情、信息编辑、布局预览和布局编辑。
- 通用二维网格画布。
- 画布尺寸拖拽调整。
- 通用元素和座位元素的创建、移动、拉伸、删除、撤回和恢复。
- 单格座位、逐格批量座位和多格合并座位。
- 使用场馆模板创建会议并生成独立布局快照。
- 场馆模板并发修改保护。
- 与本次重构相关的数据库硬删除及无外键改造。

### 2.2 本期不包含

- 场馆模板版本管理。
- 场馆模板用户级隔离、权限分级和审批。
- 代码内置或数据库初始化场馆。
- 画布旋转、元素旋转和任意角度旋转。
- 圆桌等非矩形网格元素。
- 元素编号和座位自动编号。
- 自动排座和上台路径计算。
- 模板共享范围配置。

## 3. 核心业务规则

### 3.1 全局模板

场馆模板属于系统公共资源，不按用户 ID 隔离。任意已登录用户均可查看和操作全部模板，审计字段记录实际操作人。

模板以“地点”作为业务显示名称。地点必填，去除首尾空格并忽略大小写后全局唯一。园区为可选字段，只用于列表展示、筛选和分组，不参与唯一性判断。

### 3.2 模板与会议快照

使用模板创建会议时，后端复制模板当时的画布尺寸、元素类型、元素名称、几何位置和颜色，形成会议自己的布局快照。

后续操作满足：

- 修改模板不会修改已创建会议。
- 删除模板不会删除已创建会议及排座数据。
- 删除模板后，已有会议的模板来源引用置空，但会议布局快照继续可用。
- 会议中的人员排座始终绑定会议元素 ID，不绑定模板元素 ID。

### 3.3 座位语义

元素基础类型仅分为：

- `SEAT`：可以安排人员的座位元素。
- `GENERIC`：不能安排人员的普通空间元素。

座位可以占用一个或多个相邻网格，但一个座位元素始终只能安排一个人。多个相邻座位合并后应生成一个跨格的 `SEAT` 元素，而不是多个座位元素。

座位名称可以自定义为“座位”“领导席”“嘉宾席”等，但名称变化不改变 `SEAT` 类型。其他元素名称也不对应后端枚举。

## 4. 数据模型

### 4.1 场馆模板 `t_venue_templates`

场馆信息使用普通关系型字段存储，不使用 JSONB 或属性值表。

主要业务字段：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 模板 ID | 主键 |
| `location` | 地点 | 必填，展示名称 |
| `location_key` | 标准化地点 | 去空格并转小写，用于数据库唯一约束 |
| `campus` | 园区 | 选填 |
| `main_screen_resolution` | 主屏分辨率 | 选填文本 |
| `stage_dimensions` | 舞台尺寸 | 选填文本 |
| `manual_capacity` | 人工填写容纳人数 | 选填非负整数 |
| `seat_count` | 当前布局座位数 | 后端保存布局时重新计算的冗余字段 |
| `contact_info` | 接口人 | 姓名、工号和手机号使用一个自由文本字段维护 |
| `booking_url` | 预定链接 | 选填 |
| `meeting_room_functions` | 会议室功能 | 选填多行文本 |
| `services_provided` | 服务提供 | 选填多行文本 |
| `description` | 说明 | 选填多行文本 |
| `remarks` | 备注 | 选填多行文本 |
| `grid_rows` | 画布行数 | 默认 20，最小 5 |
| `grid_columns` | 画布列数 | 默认 30，最小 5 |
| `row_version` | 聚合并发版本 | 保存信息或布局时统一校验 |
| 审计字段 | 创建人、更新人和时间 | 从 `CurrentUserHolder` 获取 |

可选文本去除首尾空格后为空时统一保存为 `NULL`。

`seat_count` 是由 `t_venue_elements` 中 `element_kind = 'SEAT'` 的元素数量计算出的布局容量，不等同于人工填写的 `manual_capacity`。两者不一致时给出提示，但不阻止保存。

以下旧字段不再保留：

- 模板名称；
- 预置标记；
- 模板版本号；
- 软删除标记；
- 舞台朝向；
- 画布旋转角度。

### 4.2 场馆元素 `t_venue_elements`

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 元素 ID | 主键 |
| `venue_template_id` | 所属模板 ID | 逻辑关联，不建立数据库外键 |
| `element_kind` | 基础类型 | 仅允许 `SEAT`、`GENERIC` |
| `element_name` | 元素名称 | 必填，可自由输入 |
| `start_row` | 起始行 | 非负且必须在画布内 |
| `start_column` | 起始列 | 非负且必须在画布内 |
| `row_span` | 占用行数 | 大于零 |
| `column_span` | 占用列数 | 大于零 |
| `fill_color` | 填充颜色 | 合法颜色值 |
| `border_color` | 边框颜色 | 合法颜色值 |
| 审计字段 | 创建人、更新人和时间 | 记录操作信息 |

元素不再维护编号、容量、可分配标记、可通行标记、分组、旋转角度和软删除字段。是否可以排座完全由 `element_kind` 判断。

### 4.3 会议元素快照

`t_meeting_elements` 保留与场馆元素相同的基础类型、名称、几何位置和颜色。创建会议时批量复制，随后独立编辑和使用。

排座关系继续通过“会议人员—会议元素”关联维护：

- 只能绑定 `SEAT` 类型会议元素。
- 同一会议元素最多绑定一名有效参会人员。
- 模板元素 ID 不进入排座关系。
- 本次场馆重构不改变人员模型和排座绑定主链路。

## 5. 页面和路由

### 5.1 首页入口

- 首页主操作“开始排座”进入 `/venues/select`，选择场馆模板后创建会议。
- 管理入口“场馆模板”进入 `/venues`。
- 已有会议继续通过会议卡片的“进入排座”进入工作区。

`/venues/select` 与 `/venues` 复用同一列表组件：

- 选择模式隐藏新增、编辑和删除等管理操作。
- 管理模式展示完整场馆维护操作。

### 5.2 场馆模板列表

列表使用表格展示，默认按更新时间倒序。

表格列：

- 地点；
- 园区；
- 人工容纳人数；
- 布局座位数；
- 更新人；
- 更新时间；
- 操作。

查询能力：

- 地点模糊搜索；
- 园区筛选；
- 每页 10、20、50 条；
- 支持“不分组”和“按园区分组”切换；
- 分组仅在当前分页结果内增加园区分组标题；
- 未填写园区的模板归入“未填写园区”。

行操作：

- 主要操作：使用模板；
- 常用操作：详情、预览；
- 更多操作：编辑信息、编辑布局、删除。

`seat_count = 0` 时显示“布局未完成”，禁用“使用模板”，但允许详情、预览、编辑和删除。

### 5.3 信息页面

新建模板采用两个全屏步骤：

1. 填写场馆信息；
2. 编辑场馆布局。

第一步不要求填写画布行列数。进入第二步时创建默认 `20×30` 画布。两步数据暂存在前端，最终保存时一次性提交，不在数据库创建临时草稿。

信息表单分组：

- 基本信息：地点、园区、容纳人数、接口人、预定链接；
- 设备信息：主屏分辨率、舞台尺寸、会议室功能、服务提供；
- 补充信息：说明、备注。

地点在失焦和最终提交时校验重名。返回上一步保留已填写数据，离开存在未保存内容的页面时二次确认。

已有模板的信息详情使用抽屉展示，信息编辑使用独立编辑抽屉。布局编辑进入全屏画布页面。

## 6. 布局编辑器

### 6.1 页面结构

布局编辑器占满可用页面空间，不展示大量说明性小字。

顶部工具栏保留：

- 返回；
- 当前地点；
- 当前画布“行 × 列”；
- 当前座位数和人工容纳人数；
- 撤回、恢复；
- 缩小、缩放比例、放大、适应画布；
- 保存。

本期不展示任何画布旋转或元素旋转按钮。

右侧属性面板可以折叠。未选中元素时显示场馆信息摘要；选中元素时显示元素属性。属性面板不以遮挡画布的浮层形式出现。

### 6.2 画布尺寸

用户不通过数字输入框设置画布大小，而是拖拽：

- 右边缘调整列数；
- 下边缘调整行数；
- 右下角同时调整行列数。

画布最小为 `5×5`。扩大画布直接生效；缩小画布如果会裁剪任何已有元素，则：

- 显示拟缩小边界；
- 高亮冲突元素；
- 拒绝本次缩小；
- 不自动移动或删除元素。

### 6.3 创建元素

用户通过单击网格或拖拽框选连续区域后选择元素。选择卡片出现在选区附近，但不能覆盖选区。

前端提供常用名称快捷项，例如：

- 座位；
- 门、前门、后门、入口；
- 智慧屏、投影、显示器、主屏幕布、辅助屏幕布、提词屏；
- 操控间、中控室、电梯、楼梯口；
- 柱子、墙、桌子、音箱；
- 伴手礼、奖杯放置、荣誉墙、装饰道具、主展板；
- 舞台、走廊、讲台。

快捷项只负责填充建议名称、基础类型和默认颜色，不进入后端枚举。用户始终可以输入任意元素名称。

选择多格区域并创建座位时提供：

- 逐格生成座位：每个网格生成一个独立 `SEAT` 元素；
- 合并为一个座位：整个选区生成一个跨格 `SEAT` 元素。

### 6.4 编辑元素

元素支持：

- 左键选中；
- 按住左键拖动位置；
- 拖动边缘或角点调整大小；
- 修改元素名称；
- 修改填充色和边框色；
- 删除；
- 撤回和恢复。

移动或拉伸过程中实时显示结果。发生越界或与其他元素重叠时显示冲突预览，并禁止确认冲突状态。

由于元素方向可以通过改变 `row_span` 和 `column_span` 表达，本期不维护旋转角度。

## 7. 保存与并发

### 7.1 新建模板

最终保存时一次提交场馆信息、画布尺寸和全部元素。后端在一个事务内完成：

1. 标准化并校验地点；
2. 校验场馆信息；
3. 校验画布和元素；
4. 写入场馆模板；
5. 批量写入场馆元素；
6. 计算并回写 `seat_count`。

任何一步失败都回滚全部数据。

### 7.2 编辑模板

信息和布局分别保存，但共享模板聚合根上的 `row_version`。

保存布局时采用完整集合替换：

1. 校验请求中的 `rowVersion`；
2. 校验完整布局；
3. 物理删除模板原有元素；
4. 批量插入本次完整元素集合；
5. 更新画布尺寸、`seat_count` 和 `row_version`。

模板元素不被其他业务直接引用，会议只持有独立快照，因此完整集合替换比逐元素差异更新更简单可靠。

发生版本冲突时不覆盖数据库内容，前端提示“该场馆模板已被其他用户修改，请刷新后重新编辑”。

## 8. 接口设计

所有控制器接口只使用 GET 和 POST，不使用 `/api` 前缀。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/venues` | 分页搜索和筛选场馆模板 |
| GET | `/venues/{id}` | 查询场馆信息 |
| GET | `/venues/{id}/layout` | 查询画布及元素 |
| POST | `/venues/create` | 创建完整场馆模板 |
| POST | `/venues/{id}/info/update` | 修改场馆信息 |
| POST | `/venues/{id}/layout/update` | 保存完整布局 |
| POST | `/venues/{id}/delete` | 删除场馆模板 |
| POST | `/meetings/create-from-venue` | 使用模板创建会议 |

接口继续使用项目统一响应结构：

```json
{
  "code": 0,
  "data": {},
  "msg": "success"
}
```

后端从 `CurrentUserHolder` 获取用户信息，前端不手工添加用户 ID 请求头。

## 9. 校验与异常

### 9.1 服务端校验

- 地点必填且标准化后全局唯一。
- 人工容纳人数为空或非负整数。
- 画布行列数均不小于 5。
- 元素名称必填。
- 元素类型只能是 `SEAT` 或 `GENERIC`。
- 元素几何范围必须完全位于画布内。
- 任意两个元素不能占用相同网格。
- 元素颜色必须是合法颜色值。
- 没有座位的模板可以保存，但不能用于创建会议。
- 创建会议时重新校验模板存在且 `seat_count > 0`。

### 9.2 友好错误

- 地点重名：“该地点已存在场馆模板”。
- 模板不存在：“场馆模板不存在或已被删除”。
- 并发冲突：“该场馆模板已被其他用户修改，请刷新后重新编辑”。
- 布局冲突：返回具体冲突元素或网格位置。
- 事务失败：整体回滚，不留下不完整模板或布局。

前端保存期间禁用重复提交，并保留用户当前编辑内容以便修正。

## 10. 删除与逻辑关联

场馆模板删除事务依次执行：

1. 将已有会议中的 `venue_template_id` 置为 `NULL`；
2. 物理删除该模板的全部场馆元素；
3. 物理删除场馆模板。

会议布局快照、参会人员、排座关系和发布版本均不删除。

本次实现同时对整个系统执行以下规范化调整：

- 所有业务表删除软删除字段；
- 删除 MyBatis-Plus 逻辑删除注解和逻辑删除查询条件；
- 所有业务删除改为物理删除；
- 数据库不创建任何外键或级联约束；
- 后端以聚合为单位，在事务中显式清理子表和逻辑引用；
- 删除会议、人员、排座方案等聚合时，必须由对应服务明确清理顺序；
- 仓储层不得依赖数据库级联完成业务删除。

本设计中关于硬删除的决定覆盖此前设计文档中与软删除有关的描述。

## 11. 数据库与代码迁移

实施阶段需要：

- 删除场馆预置定义、预置目录和预置合并查询逻辑；
- 删除应用启动时的场馆初始化代码；
- 调整场馆模板和元素实体；
- 调整会议快照复制逻辑；
- 调整场馆列表、详情、预览和编辑接口；
- 调整首页和场馆相关路由；
- 删除业务实体的软删除字段与注解；
- 删除全部数据库外键定义；
- 重新整理根目录 `DDL/meeting_helper.sql`。

DDL 文件继续满足：

- 只包含 `CREATE TABLE` 语句；
- 不包含 `ALTER`；
- 所有表名使用 `t_` 前缀；
- 所有表和字段均包含注释；
- 不包含数据初始化语句；
- 不包含数据库外键。

完成 DDL 修改后，删除本地 PostgreSQL 中现有业务表，并仅使用 `DDL/meeting_helper.sql` 重建数据库结构。本次开发环境数据不做迁移保留；生产数据迁移方案不在本期范围。

- PostgreSQL 下验证完整 DDL 建表，不使用 H2。
- 场馆分页、地点模糊搜索、园区筛选和分组。
- 地点标准化和全局重名校验。
- 信息保存和布局保存的乐观锁冲突。
- 画布范围、元素重叠和颜色校验。

## 13. 验收标准

- 系统中不存在代码预置场馆和自动初始化场馆数据。
- 所有用户看到并操作同一套场馆模板。
- 场馆模板可按地点搜索、分页并按园区分组。
- 场馆信息字段完整，只有地点必填。
- 用户无需输入行列数即可进入默认画布，并能拖拽调整画布大小。
- 座位和普通元素能够自由跨格，座位元素始终只容纳一人。
- 元素名称完全可扩展，不依赖场景枚举。
- 模板不维护业务版本，保存后直接更新当前模板。
- 模板修改和删除不影响已有会议快照。
- 所有业务表使用物理删除，数据库无外键约束。
- 所有场馆编辑并发冲突均不会静默覆盖他人内容。
- 本期无任何画布或元素旋转功能。
